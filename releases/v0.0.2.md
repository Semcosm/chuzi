# chuzi v0.0.2

`v0.0.2` fixes the Windows launcher UI startup path that could produce a blank
WebView2 window in `v0.0.1`.

Highlights:

- Load the embedded launcher UI after the native WebView has been created,
  avoiding the failing initial in-controller HTML navigation path.
- Keep the inline-page navigation policy strict and case-sensitive; external
  and file URLs remain denied.
- Add opt-in `CHUZI_LAUNCHER_UI_DIAGNOSTICS=1` stderr diagnostics for the
  WebView runtime, page-load transitions, blocked navigation, and native
  script/load errors.

The release keeps the existing launcher protocol, component management
surface, and cross-platform package layout. Production-grade real-account
browser automation, a production Matrix network client, and full deployment
orchestration remain outside this release.

Installation and platform prerequisites are documented in
[`RELEASE.md`](../RELEASE.md) and [`docs/operations.md`](../docs/operations.md).
